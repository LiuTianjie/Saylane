# Saylane 截屏翻译：效果契约与实现交接

> 2026-09-16：后续轻量版面与性能工作以 [最新实施方案](SCREEN_TRANSLATE_NEXT.md) 为准。用户已认可 0.2.60 原位覆盖，并允许容器内段落排版及局部滚动；下文旧版“仅逐行、无滚动”和版本信息不代表当前状态。

更新：2026-09-13。本文是**目标效果**的实现契约，不代表当前源码已经做到。  
现有 `Sources/Services/ScreenTranslate*.swift` 是半成品，经历过多轮错误方向（整页重排、灰罩、框在转），**不要把当前实现当设计**。下一轮按本文重做或大幅改，而不是在旧 overlay 上继续打补丁。

产品：Saylane（`/Users/turning4th/rtranslate`），macOS 输入法。本功能是输入法里的 **⌥T 截屏翻译**（可改快捷键），不是独立截图 App。

---

## 1. 一句话

用户划一块屏幕 → 这块区域**钉在原地、像素 1:1** → 原文先完整露出来 → 识别+翻译完成后，**只在原来的文字位置贴译文** → 图、气泡、代码、头像、卡片底全部还是原图像素。

参考对象：PixPin 的划选手感；视觉上最接近用户满意的是「对话气泡上贴一行行译文」那一版（见 §4 图3），不是后来的文章重排。

---

## 2. 范围

### 现在做（Phase 1）

静态截屏翻译。划完就冻结画面，翻译这一帧。

### 明确以后再做（Phase 2，本轮不要做）

持续翻译：框住一块区域后，区域内画面变化也跟着翻（聊天软件里新气泡出来就翻）。交互可以以后做成「钉住一块 live overlay」。本轮不要上定时截屏循环。

### 不要做

- 不要整页重排成一篇新文章
- 不要把框选结果做成可拖动的缩放卡片
- 不要对非文字区域重新编码/模糊/铺灰
- 不要让边框、卡片、原图发生旋转、缩放、位移
- 不要在译文没出来之前先用 OCR 原文或低清层盖住画面
- 不要为了 hover 吸附去上 DocLayNet / YOLO 等版面大模型（见 §6）

## 3. 交互

### 3.1 入口

- 默认快捷键 **⌥T**（`ScreenCaptureShortcut.optionT`），设置里可改。
- 需要屏幕录制权限；没有权限时说明原因，引导去系统设置，不要静默失败。
- 触发后进入划选，不改变语音输入的翻译方向。

### 3.2 划选

全屏半透明遮罩（未选中区域变暗）。两种取框，可并存：

1. **拖动**：按住拖出矩形，松开即截取该矩形。
2. **点选吸附**：鼠标移动时预览一个高亮框；单击采用该框。用户随时可以改成自己拖。

吸附优先级（从紧到松）：

1. 指针下的**内容块**（一条推文、一张卡片、一个气泡、一段正文栏）
2. 指针下的**窗口**
3. 没有可吸附对象时只显示提示，让用户拖

高亮框：圆角、细描边，类似 macOS 截屏的窗口高亮。不要厚阴影、不要把预览框做成缩放后的缩略图。

提示文案跟在指针旁即可，例如：

- 未拖动：`中→英  ·  点击框住，拖动自选`
- 已吸附到块：`中→英  ·  点击框住这一块`
- 拖动中：`中→英  ·  松开翻译`

Esc / 右键取消。

### 3.3 钉住（pin）

松开或点击确认后：

1. 立刻按选区 **屏幕坐标原位** 盖住该矩形。
2. 这一层的内容必须是刚截到的原图像素，**点对点对齐**，肉眼不能看出缩放、位移、变糊。
3. 此时**还没有译文**。用户看到的就是「这块屏幕被框住了」：原图 + 圆角描边。
4. 识别/翻译进行中：只允许描边做**彩色流光**（颜色在描边路径上走）。  
   **禁止**：整框旋转、整层旋转、缩放呼吸、位移抖动。流光的 mask 必须是固定圆角矩形路径，只能转动/滚动渐变颜色。
5. 译文就绪后，在原文字位置淡入贴字（见 §4）。不要先出一层糊的，再突然变清晰。
6. 左下或选区下方一条小胶囊工具条（不挡住内容）：
   - `译文` / `原文` 切换（空格也可）
   - 当前方向 `中→英`，点击或快捷键切换
   - 状态：`正在识别`、`正在翻译`，**整词显示，禁止省略号裁切**
   - `复制`、关闭
7. Esc 关闭。⌘C 复制。

### 3.4 翻译方向（关键）

语音输入的方向和截屏翻译的方向**隔离**。

- 截屏界面里，原来用来切换语音方向的那个快捷键，在本界面**只切换截屏翻译方向**。
- 退出截屏后，语音方向保持原样，不能被这次 ⌥T 改掉。
- 截屏自己的方向可记住上次（UserDefaults），但不要写回语音方向。

语言对来自设置里的 A / B 两种语言，截屏在 `A→B` 与 `B→A` 之间循环。不要出现 `中→中` 这种语音听写模式。

## 4. 视觉：什么叫「原地贴字」

### 4.1 用户认可的效果（必须对齐）

用户给过一张**对话气泡**截图，评价：「最开始那种感觉我还挺满意」。那一版的特征是：

- 头像、气泡形状、绿色/灰色底、时间戳、整页背景全部是原图
- 每一行原文上盖一条贴片，贴片上是译文
- 气泡仍然是气泡，没有变成一篇左对齐文章
- 唯一不满后来被澄清为：**框和原图没有像素对齐**（看起来像缩放/位移），以及翻译中的流光把**整个框转起来了**（错误实现）

同一需求在论文/推文上的推论：

- 论文插图、公式图、页边：原图像素
- 推文里的代码截图、媒体预览：原图像素
- 只有「像句子的字」被替换

### 4.2 贴片规则（逐行，不要整段重排）

以 Vision OCR 的**每一行** `boundingBox` 为单位，不要把多行合成一个大段落再往下推。

对每一行：

1. 用该行框在原图上取样**纸色/气泡底色**（取框边缘像素的中位数，不要对整框含字墨求平均，否则白纸黑字会变成灰条）。
2. 用圆角条盖住原文字（半径约 `min(5pt, 行高/2.4)`），颜色就是取样到的底色，让原字消失。
3. 在这条里画译文：
   - 字号 ≈ 该行 OCR 框高度 × 0.78～0.82，**用这一行自己的高度**，不要用整页中位数。
   - 颜色与底色对比：浅底深字，深底浅字。
   - 对齐跟原文：如果原行墨迹左右都明显留白（气泡居中），译文居中；否则左对齐。
   - 单行垂直居中。
   - 译文比框长：在框内换行并裁切；**禁止把后面的行往下挤**，禁止把画布拉长成一张长文。
4. 非文字像素（含被判定为代码/行号/路径的 OCR 行）完全不盖。

代码/机器文本不要翻译、不要盖片。启发式即可：`const `/`function `/`=>`、成对括号、行号、引号字符串、符号密度过高等。误伤时优先「留下原图」而不是「错翻代码」。

### 4.3 钉住窗口的几何（硬约束）

设选区为屏幕 AppKit 坐标 `rect`，截到的 `CGImage` 像素为 `rect.size * backingScale`。

- pin 窗口的**图像层**屏幕坐标必须等于 `rect`
- 图像层 point 尺寸必须等于 `rect.size`
- `contentsScale` 必须等于 `cgImage.width / rect.width`，禁止 `scaleAxesIndependently` 拉伸
- 禁止 `shadowOffset`（`(0,-2)` 这种会让人觉得整块挪了）
- 流光描边可以画在 `rect` 外侧 8～10pt 的透明边里，但原图本身仍在 `rect` 里
- 不要 NSScrollView 包原图

验收：框住后，如果还没出译文，把钉住层和底下真屏幕比，应像没截过。不能先糊后清。

### 4.4 复制

复制的是「原图像素 + 已经贴好的译文」，尺寸与原截图相同。

- 在 **CGImage 原生分辨率**上画贴片，不要截 pin 窗口的低清 backing
- 非文字区域必须和原 `CGImage` 逐像素一致（或视觉不可辨）
- 不要用 SwiftUI `ImageRenderer` 另渲染一篇白底文章
- 译文要完整写进对应行框；框内裁切可以，但不能只截当前滚动视口（Phase 1 根本不应出现滚动画布）

## 5. 流水线

```
⌥T
 → 划选（吸附或拖）
 → ScreenCaptureKit 只截这一块（不含光标，尽量排除自己的划选遮罩）
 → 立刻 pin 原图（§4.3）+ 固定圆角框 + 流光
 → 并行：OCR ∥ 准备 Translation 引擎
 → OCR 行列表（Vision accurate）
 → 过滤机器文本
 → 按行翻译（用换行拼成一篇，按行数拆回；行数对不上就逐行翻）
 → 原图上贴译文（§4.2）
 → 流光停，留下静态细描边
```

翻译引擎：现有 `TranslationEngine`（系统 Translation 框架）。截屏方向与语音方向隔离，见 §3.4。

OCR 语言：带上当前方向的 source/target identifier。

## 6. 吸附「块」怎么做（不要上大模型）

用户希望 hover 时不只吸窗口，还能吸到矩形/卡片/气泡。

**不要**为 hover 引入版面分析模型（DocLayNet、Paddle Structure、YOLO-layout 等）：权重大、要先截屏再推理，hover 必须 <16ms 量级。

推荐两层，失败则退回窗口：

1. **Accessibility 命中**  
   `AXUIElementCopyElementAtPosition`，沿父节点收集 frame，取**包含指针、比按钮大、比窗口小**的最小块（Group / Cell / Row / 气泡容器）。无辅助功能权限就跳过，不要弹权限打扰划选。
2. **窗口内容里的色块**  
   用该窗口自己的图像（`CGWindowListCreateImage` 只含目标窗口，不含我们的遮罩），从指针做背景色外扩/四向找边，得到均匀底色的卡片框。节流（≥50ms）并按 windowID 缓存图像。

几何选择：在窗口框和所有候选块里，取包含指针、面积最小、且面积 < 窗口 90% 的那个。太小（图标）丢掉。

用户仍可拖动覆盖任何吸附。

已知错误方向（不要复活）：

- 把所有 OCR 合成段落，按阅读顺序 **Y 方向重排**，复制成超长条
- SwiftUI 整列 `ScrollView` 铺一层纸色，NSHostingView 默认不透明 → 满屏灰罩
- `NSImageView.scaleAxesIndependently` + `shadowOffset` → 像缩放/位移
- 给带圆角 mask 的 **同一层** 做 `transform.rotation` → 整框在转
- 翻译未完成就用错误字号/灰条盖住原图 → 「先低清再高清」

## 8. 验收

用同一块屏幕，肉眼对比「未翻」和「已翻」：

1. **对话气泡**（用户最满意的类型）：气泡形状、颜色、头像不变；每行译文落在原文字上；居中的气泡译文也居中。
2. **推文/时间线**：推文卡片结构不变；嵌入的代码截图/图片不被翻译、不被灰条盖住。
3. **论文段落**：插图保留；正文左对齐贴字，不要变成居中药丸。
4. 框选完成到译文出现之前：原图与真屏幕对齐，只有描边在流光，框不转、不缩、不挪。
5. 工具条「正在识别 / 正在翻译」四个字写全。
6. 切换译文/原文：原文 = 纯截图；译文 = 截图+贴片。
7. 复制图尺寸 = 原截图像素尺寸；粘贴到预览里，非文字区与原图一致。
8. 截屏里切 `中→英` / `英→中`，退出后语音方向不变。
9. 构建与安装成功不算验收；必须用 ⌥T 在真实屏幕上划上述三类内容。

## 9. 给实现者的顺序

1. 先做 **1:1 原位 pin**（§4.3）+ 固定描边，确认「未翻译时看不出截过」。
2. 再做 OCR 后的 **逐行贴片**（§4.2），对齐图3那种气泡感。
3. 流光只加在描边 mask 上，验证框本身绝对不转。
4. 复制走原图像素合成。
5. 最后才做内容块吸附（§6）；做不完可以先只吸窗口，拖选必须能用。

不要并行重做 Phase 2 持续翻译。
