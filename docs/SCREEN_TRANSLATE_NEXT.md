# 截屏翻译：轻量版面与流畅体验实施方案

日期：2026-09-16。状态：模型评测、排版和交互改动已在工作区实现；新增三场景实测未通过，暂停打包。详见 SCREEN_TRANSLATE_SCENARIOS.md。

## 决策与基线

以用户认可的 0.2.60 / b2a5174 为回退基线。工作区随后增加的上下文润色与溢出 tooltip 是独立的未提交改动，保留并单独验证。

本轮采用 Vision OCR + 几何/像素边界分析 + 苹果本地翻译 + 原生覆盖渲染。小型版面模型作为待验证的辅助检测器，不引入 GB 级语言模型。模型不生成最终坐标、字号或截图。

最新用户要求优先于 SCREEN_TRANSLATE.md 中旧版逐行、无滚动约束：允许容器内段落合并、空白范围扩展和局部滚动；原截图、图片、按钮外形仍保持原位。不会用翻译长度推动原截图像素。

## 候选模型与准入条件

- 首先评测 PP-DocLayout-S。官方推理权重约 4.8 MB，仓库合计约 5.16 MB，训练场景主要是论文、杂志、书籍、试卷等文档。它不是已经验证的网页 UI 检测器，不能据此保证按钮识别效果。
- ONNX 是部署格式，不是模型能力。核对导出前后框、类别、置信度、缩放还原与 NMS 一致性；Mac 上比较 ONNX Runtime 与可转换的 Core ML 路径，按准确性、耗时和新增包体选择，不预设某个后端必然更快。
- 将模型权重、运行时库、初始化内存一并计入成本。首个候选目标为权重不超过 10 MB，新增发行包体不超过 30 MB；不满足则回到无模型方案或重新评估。
- OmniParser v2 的图标检测权重约 40.6 MB，仅作为 UI 检测对照资料，不引入完整图像描述流水线，也不作为首选依赖。
- 小模型只有在真实截图上降低错误合并/遮挡、同时满足延迟预算时才启用；不把文档测试集成绩当网页截图证据。

## 流水线

1. 截图后立即显示原始像素。OCR、翻译模型准备、缩略图边界分析在后台并行。
2. 保留现有高分辨率 OCR 分块，避免整图缩小后丢小字。坐标统一到原截图像素，再统一转换为显示点；不混用横纵归一化距离。
3. 版面分析生成容器、非文字保护区与置信度。模型框只是候选；OCR 几何、分割线和像素边界共同约束，不能因为漏检就认定某块为空白。
4. 在同一容器内按基线、字高、间距和对齐合并正文。标题、按钮、用户名、统计数字分别保留，禁止跨栏和跨卡片合并。
5. 苹果翻译按稳定 ID 批量执行；相同原文、方向、语义角色使用会话内缓存。截图关闭后释放截图相关分析结果。
6. 译文在容器内确定性排版，得到稳定布局快照，再一次提交到原生视图。原图和非文字保护区不重绘、不分片移动。
7. 检测失败或超过等待预算时，使用现有安全布局。晚到的检测结果不让已显示译文再次跳位置。方向切换、关闭和新截图使旧任务失效。

## 排版与交互

- 字号以原文像素和字形估计为准，按局部文字样式校准，禁止根据译文长度缩字号。
- 正文在容器内按段换行；只使用经像素和邻居检查确认的空白，不穿过图片、按钮或其他译文。
- 按钮文案在确认的按钮内框居中，不能把 OCR 字框误当整个按钮。边界不确定就保守保持当前位置。
- 溢出保留局部滚动，并提供轻量的完整译文浮层；明确操作入口、Esc 关闭、复制完整文字。浮层属于用户主动打开的辅助层，不改变原截图布局。
- 用 NSScrollView 处理滚动，避免主线程重建整页。关闭/重开、原文切换、方向切换、鼠标滚动及复制分别验证。
- 保留用户认可的文字背景模糊效果，调整只发生在文字遮罩内。

## 用词与速度

版面检测不能自行翻译。先通过正确段落分组改善上下文；确认 UI 角色及界面语境后，才使用少量可测试的常见 UI 术语规则。比如 Post 不能在所有文章中无条件替换成“发布”。用户名、URL 和产品名优先保留。

现有可选网络润色不成为默认首屏的依赖，不自动启用。它与本轮版面工作分开测试和报告；本轮不下载或集成 Qwen 语言模型。

## 性能目标（验收门槛，不是已测结果）

- 同机同图与 0.2.60 进行配对测试，分别记录冷启动与热启动。
- 松开选区到原图显示目标 p95 <= 100 ms。
- 后台版面分析目标热运行 p95 <= 100 ms，首轮等候上限 150 ms；预算到期忽略结果，不能在 UI 线程等待同步推理。
- 翻译首屏 p95 不比基线增加超过 150 ms。现有约 4.2 秒数据仅是单张图 OCR、翻译、静态导出总和，不是首屏或 p95。
- 60 Hz 设备滚动/切换时，主线程单帧工作目标 p95 <= 16.7 ms；120 Hz 设备单独报告。
- 同时报告峰值内存、初始化成本与重复使用后的驻留内存，不以模型文件大小代替运行内存。

## 实施顺序与交付

1. 保存固定截图基线与关键区域标注：现有 X 页面，补聊天气泡、深色 UI、按钮密集页、双栏文档、图片文字与代码；每图制作整图及多个不同边距裁切。先建立耗时、框匹配、遮挡、溢出和字号偏差报告。
2. 离线比较无模型边界分析与 PP-DocLayout-S；先画检测框，不改正式渲染。仅通过准入门槛的方案进入应用。
3. 接入统一容器/保护区数据，改段落分组和布局；每一步与 b2a5174 的截图对照，防止较小截图退化。
4. 优化批量更新、会话缓存、任务取消和溢出完整阅读交互。
5. 测试静态导出和真实 macOS 操作：原位覆盖、滚动、切换、取消、复制。保护区域像素对比必须通过；视觉检查单独给出结论。
6. 分别提交模型评测、版面/排版、交互性能改动。全部验收后再生成新版本安装包；构建成功不等于体验验收。

模型未通过时交付无模型改善，不为“用了模型”牺牲现有体验。最终报告明确哪些指标改善、哪些截图仍失败，以及实机安装状态。
