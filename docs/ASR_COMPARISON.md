# 可切换语音识别试用版

> 0.6.0 起：下载的模型只写终稿，说话时的字由系统识别显示，单次 30 秒的上限已取消。现行做法和实测数字见 `docs/SPEECH_PIPELINE.md`；下文是当时的记录。

2026-09-17，0.2.64。本轮承接“设置中切换模型比较，然后打包安装”的需求。

## 使用

设置 → 本地模型中提供 Apple、Qwen3-ASR 0.6B 4-bit / 6-bit、SenseVoiceSmall Q8、Fun-ASR-Nano Q4。下载后点“使用”；当前模型卡和顶部状态显示选择与就绪状态。每个本地模型可单独修复或删除；切换先取消并释放旧识别任务。

开启“仅识别，暂不翻译或润色”直接输入识别原文，沿用设置中的说话语言。不准备翻译模型，不调用翻译或润色 API。关闭开关恢复原有设置，不覆盖原来的润色选项。

“Qwen 个人热词”默认关闭，词表在本机偏好中保存。最多使用 50 个不重复词条，每条 80 字、总计 1000 字；每次会话冻结配置，经私有进程管道传入 Qwen context。其他三个引擎当前不接收这些热词。热词提示不等于准确率保证。

## 运行与分发

- Apple 保留实时组字。本地模型按住说话时对不断增长的录音做短间隔重识别，通过现有 marked text 刷新预览；松开时若已有结果精确覆盖全部录音，直接复用；否则补做完整识别。这不是常驻流式服务，也不是官方 CLI 的 stdin 流。Fun-ASR-Nano 更重，预览间隔更长。Qwen 预览不能中途杀掉常驻进程，松手时会等当前预览结束；完全覆盖录音的结果直接成为终稿，否则识别最新的完整录音。取消整个会话时会回收该进程，下次重新加载。每次最多 30 秒。
- SenseVoice 本机短句加载加推理约 0.1–0.2 秒，因此预览较密；Fun-ASR-Nano 更重，预览较疏。Qwen 沿用独立常驻 MLX 进程，预览与最终识别共用该进程。
- 新引擎自动识别所支持的语言；应用的说话语言仍决定允许启动的语种、中文简繁转换及后续翻译方向。当前 CLI 不提供语言强制指定及热词参数。
- SenseVoiceSmall 权重约 254 MB；Fun-ASR-Nano 两个权重合计约 954 MB。仅在点击下载后保存至原有 Application Support/RTranslate/ASRModels 目录。开发验证已将上次下载且通过 SHA-256 校验的这两个模型放入本机该目录，可以直接试用。
- 安装包携带约 8.3 MB 原生程序，不携带语音权重、Python 或训练环境。运行程序压缩包版本和 SHA-256 在 Vendor/FunASR/runtime.lock.json；模型清单固定仓库、revision、文件大小与 SHA-256。
- 每次录音转换为 16 kHz 单声道，在权限 0700 的随机临时目录写 WAV，推理结束或取消后删除。取消/60 秒超时终止并回收子进程；不会把录音写入诊断日志。
- 打包逐个签名识别程序，再签名应用；当前机器无 Developer ID Installer 证书，因此 PKG 未签名，应用本身已签名。

## 验证记录与边界

- Release 构建和 scripts/test.sh 全套回归通过，包含已有输入法、语音会话、模型下载校验、生命周期与屏幕翻译检查。
- 新增 scripts/test-native-asr.sh：真实进程输出、启动前取消、运行中取消与回收、非零退出、16 kHz 单声道 WAV 格式通过。ASRModelTests 补充两个模型清单、语种限制及热词规范化检查。
- 用签名后的包内应用通过 --recognize-file 运行已有中文、英文和静音样例。两个新模型中文均输出“甚至出现交易几乎停滞的情况。”，英文均返回转写，静音均为空且未调用识别程序。
- Debug 原生设置预览实际点击 Apple → SenseVoice → Fun-ASR-Nano → Qwen 4-bit → Qwen 6-bit → Apple，全部显示对应“已就绪/使用中”；仅识别和热词开关可正常切换，已恢复 Apple 与两个开关关闭。预览不注册第二个输入法服务，尚不等于安装后跨应用麦克风输入验证。
- Qwen 4-bit 通过 --speech-hotwords 传入“交易，停滞”后识别中文样例成功。该检查只证明参数链路可运行，不能证明热词提高了该条准确率。
- SenseVoice 英文样例末尾曾出现 `io>`，现仅删除残留标签片段，不补词。Fun-ASR-Nano 该条仍全部大写。短样例只证明链路可运行，不能据此排名。
- 用同一中文样例的 1/2/3 秒前缀实测 SenseVoice CLI：约 0.11–0.14 秒返回，文本随音频变长而变完整。这是离线进程重跑，不是逐帧流式解码。
- 日常口音、噪声、长句、热词收益仍需实际使用比较。本轮没有引入准确率排行榜，也没有把新引擎改成默认模型。
