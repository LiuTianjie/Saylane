# 屏幕翻译三场景实测（2026-09-16）

初轮结论（下方保留当时数据；后续修复见文末）：当时工作区未通过视觉验收，不能用“矩形不重叠”代替“文字完整”。没有生成或安装新版包。基线仍为 b2a5174 / 0.2.60；本报告测试的是未提交工作区。

## 方法

直接读取用户提供的三张原始 PNG（不使用对话压缩图），执行实际 Vision OCR → 苹果已安装的英译中模型 → 生产 ScreenPinRenderer 导出。未调用网络润色，没有模拟译文。按截图 2 像素对应 1 点处理。三张顺序运行，避免同时竞争翻译会话。

复现：`bash scripts/test-screen-scenarios.sh paper.png x.png chat.png`。输出位于 `build/tests/scenarios/{paper,x,chat}/`，包含 translated.png、原始 OCR 坐标和文本 ocr.txt、布局与耗时 report.txt、run.log。截图包含私人内容，不加入 Git。

脚本逐张收集结果；任何一张发现指定 OCR 文本缺失、译文块隐藏、没有完整行可见、指定保护区域像素改变，就返回非零。本次整体退出码 1。检查仅针对这些已知样例；不能取代人工检查译词、段落和整体视觉效果。

## 论文专项修复复测

用户确认 X 和聊天当前效果满意，本轮只为密集单栏文档启用新路径，不调整这两个场景。

- 用长行数量、列宽和左边缘一致性识别密集单栏正文；该分类不依赖文件名或论文术语。
- 即使图片小于 2200 像素，也对这种文档执行现有的原分辨率分栏补识别。本文由 46 行恢复为 49 行，Attention mechanisms 段的三行恢复。
- 依据正文的典型行距分开自然段，由 7 块改为 12 块（3 个标题、9 个正文段落）。
- 正文共享稳健字号估计，本例正文统一为 13.1 点；限制译文在原文列宽内排版，避免占满右页边距。
- 实际苹果翻译复测：无隐藏、无空白块、无溢出、无正面积重叠；人工检查整张导出图，段落完整显示。新增样例断言验证 12 个段落块及正文一致字号。
- 单轮 OCR 1.76 秒、翻译准备与翻译 1.55 秒、导出 0.14 秒，总计约 3.45 秒。额外 OCR 增加约 0.9 秒，不将其描述为免费优化。
- X 仍为 96 行 / 87 块；聊天仍为 34 行 / 21 块；两者各项隐藏、空白、溢出、保护区计数与初轮相同。用户认可其效果不等于原有严格检查已通过。

## 列表字重误判修复
